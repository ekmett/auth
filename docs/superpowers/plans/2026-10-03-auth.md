# Auth implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax for tracking.

**Goal:** Run the same authenticated tree computation as prover and verifier with an implicit database.

**Architecture:** One C++26 module contains checked binary streams, SHA-256 proofs, and scoped database state. One executable exercises serialization, replay, rejection, and context behavior.

**Tech Stack:** Homebrew Clang 21, C++26 modules, installed OpenSSL 3.

**Spec:** `docs/superpowers/specs/2026-10-03-auth-design.md`.

## Global constraints

- No explicit database argument in application functions or `Db::auth`/`Db::unauth`.
- One serialization definition for read and write; fixed-width little-endian integers.
- SHA-256 and digest-only nested proofs; no hash consing in this version.
- TLS by default, opt-in reserved AArch64 `x28`; exceptions remain active in release builds.
- Only `auth.ccm` and `auth-test.cc` for implementation and tests; no build framework.

## Review focus

- Empty byte buffers and maximum-width integers must round trip without undefined shifts.
- Noncanonical booleans and application tags must fail even with a matching frame hash.
- Failed openings must not consume a tape entry.
- Moving a resident proof must not leave a second usable moved-from value.
- Nested contexts and exceptions must restore the previous binding; separate threads must be isolated.

## Task 1: Binary serialization

**Files:** `auth.ccm`, `auth-test.cc`.

**Interfaces:** `bytes`, `digest`, `encode(const T&)`, `decode<T>(span<const uint8_t>)`, `sha256(span<const uint8_t>)`; streams support `operator()` for fields and `static constexpr bool reading`.

## Task 2: Proofs and implicit databases

**Files:** `auth.ccm`, `auth-test.cc`.

**Interfaces:** `proof<T>`, `prover::auth(T)`, `prover::unauth(proof<T>)`, verifier equivalents, `db_scope`, `verifier::finish()`. Prover owns `tape`; verifier borrows it and owns a cursor.

- [x] Implement proofs with private resident values and mode-checked backing state, TLS and `x28` bindings, and transactional verifier cursor advancement.
- [x] Build and run the suite in TLS and `x28` modes, each with and without `NDEBUG`; run sanitizers on TLS. Document runnable build commands in the test file.
- [x] Review the complete change, fix correctness findings with reproducing checks, and commit the verified implementation.

## Verification results

Both missing-module/API test compilations failed before their implementations were added. The completed suite passes with Homebrew Clang 21 in TLS and x28 modes, each with and without `NDEBUG`; TLS also passes AddressSanitizer and UndefinedBehaviorSanitizer. Independent review found a throwing return move could consume a verifier frame. The regression failed before the fix and passes afterward with `-fno-elide-constructors -DAUTH_TEST_NO_ELISION` in both TLS and x28 release builds. All seven configurations pass with warnings treated as errors.

The implementation remains in the original checkout on `codex/auth-port`. Proofs are move-only in this first version. Serializer determinism, transcript lifetime and immutability, and binding a scope at x28 ABI entries remain caller obligations as described in the spec.
