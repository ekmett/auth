# Auth implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax for tracking.

**Goal:** Run the same authenticated tree computation as prover and verifier with an explicit database argument.

**Architecture:** Separate C++26 modules provide checked binary streams, hashing, and authenticated databases, with a shared error module. The implementation tests cover serialization, replay, rejection, and independent instances; a separate importer tests the main API alone.

**Tech Stack:** Homebrew Clang 21, C++26 modules, installed OpenSSL 3.

**Spec:** `docs/superpowers/specs/2026-10-03-auth-design.md`.

## Global constraints

- Application functions take a database reference as `db auto& db` and call ordinary `db.seal`/`db.unseal` methods; arbitrary compatible implementations are supported.
- One serialization definition for read and write; fixed-width little-endian integers.
- SHA-256 and digest-only nested sealed values; no hash consing in this version.
- No TLS, reserved registers, context scopes, common database base, or runtime kind tags; exceptions remain active in release builds.
- Module interfaces in `auth.ccm`, `hash.ccm`, `serialization.ccm`, and `error.ccm`; tests in `auth-test.cc` and `auth-api-test.cc`; CMake and CTest provide the build and test entry points.

## Review focus

- Empty byte buffers and maximum-width integers must round trip without undefined shifts.
- Noncanonical booleans and application tags must fail even with a matching payload hash.
- Failed openings must not advance the tape cursor.
- Prover sealed values always contain a value, have no default empty state, and use ordinary C++ copy and move semantics; callers must not reopen a moved-from sealed value.
- Interleaved database instances must retain separate tapes and verifier cursors.

## Task 1: Binary serialization

**Files:** `serialization.ccm`, `hash.ccm`, `error.ccm`, `auth-test.cc`.

**Interfaces:** `bytes`, `digest`, `encode(const T&)`, `decode<T>(span<const uint8_t>) -> pair<T, const uint8_t*>`, `sha256(span<const uint8_t>)`; streams support `operator()` for fields and `static constexpr bool reading`.

- [x] Implement the checked reader and writer and shared member serialization dispatch with OpenSSL SHA-256.
- [x] Compile and run the tests with `-std=c++2c -Wall -Wextra -Werror`; expect success.

## Task 2: Sealed values and explicit databases

**Files:** `auth.ccm`, `auth-test.cc`, `auth-api-test.cc`.

**Interfaces:** the `db` concept, the `sealed<DB, T>` alias, and associated `prover::sealed<T>` / `verifier::sealed<T>` class templates; ordinary `prover.seal(T)` and `prover.unseal(sealed<T>)` methods, verifier equivalents, and `verifier.finish()`. Prover owns `proof` directly; verifier borrows it and owns a cursor. Helpers take `db auto& db` and callers pass the owning database directly.

- [x] Add the recursive tree replay (result `2`, three openings totaling 135 bytes without framing), digest-only sealed-value equality/serialization, altered/missing/extra/malformed bytes, failed-open cursor preservation, sealed-value copy and move checks, a third database implementation and interleaved independent database instances. Compile to demonstrate missing sealed-value/database APIs.
- [x] Implement associated sealed types with private resident values in prover mode and only the digest in verifier mode, the `db` concept, directly referenced databases, and transactional verifier cursor advancement.
- [x] Build and run the suite with and without `NDEBUG`, with sanitizers, and with copy elision disabled. Document runnable build commands in the test file.
- [x] Review the complete change, fix correctness findings with reproducing checks, and verify the implementation.

## Verification results

CMake's release and AddressSanitizer/UndefinedBehaviorSanitizer builds pass all three CTest targets: the full suite, the main-module-only API example, and the return-move regression with copy elision disabled. The latter verifies that a throwing return preserves the verifier cursor. A separate CMake consumer builds and runs through `auth::auth`. Tests also cover a third db implementation, independent db instances, and updates to the caller's db through generic helpers.

Prover sealed values are copyable when their payload supports copying; move-only payloads yield move-only sealed values. Verifier sealed values are copyable digest values. Compile-time checks verify the concept rejects missing or incorrectly typed operations and that verifier sealed values remain 32 bytes for both small and large payloads. Serializer determinism and transcript lifetime and immutability remain caller obligations.

Optional `auth_docs` generates HTML and XML with Doxygen 1.18, treating warnings as errors and repairing module navigation anchors using the helper from `ekmett/native`.
